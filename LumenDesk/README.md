# LumenDesk: RAG-помощник по документам компании

Создайте с помощью ИИ RAG-помощника для поддержки LumenDesk — вымышленной платформы совместной работы. Исходные данные — **50 документов в папке [documents](documents/)**: тексты, таблицы, PDF и Word на русском, английском и французском.

Работайте в отдельном приложении ИИ или в VS Code с расширением ИИ, которое имеет доступ к папке проекта и может выполнять команды. Под «чатом ИИ» понимается чат в этом приложении или расширении.

Разберите материалы, переведите английские и французские тексты на русский язык и подготовьте единую базу. Сохраните оригиналы и связь переводов с ними. Самостоятельно разберитесь с дублями, старыми версиями, черновиками и ограничениями доступа.

Постройте поиск по подготовленной базе. Помощник должен отвечать на русском языке, ссылаться на проверяемые места в оригиналах, уточнять недостающие условия и обозначать ситуации, в которых нужен человек.

**Докажите, что RAG работает:** задайте вопросы по документам через настоящий поиск, сверьте ответы с документами и сохраните результаты и скриншоты из чата ИИ. Покажите работу с таблицами, переводами, повторами, противоречиями и ограничениями доступа.

## Запуск на macOS

В каталоге `LumenDesk` нужен Python 3.12. При первой сборке понадобится доступ к Hugging Face для загрузки весов поиска. Для контрольных запросов и составления ответов из чата Codex отдельный API-ключ не нужен.

```sh
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-rag.txt
python extract.py
python rag.py build
python rag.py search --role support_agent "Какой предел одного вложения на Team?"
```

В чате Codex откройте каталог проекта и задайте вопрос вместе с ролью. Попросите выполнить команду `rag.py search`, сформулировать ответ только по её выдаче и сохранить итог через `rag.py save-answer RUN payload.json`. В выводе поиска есть `RUN` и идентификаторы фрагментов. Файл с ответом содержит `decision`, русский текст `answer` и массив `citations`. Для каждой цитаты передайте `hit`, `fragment` и дословный отрывок из поля `text` найденного фрагмента. Формат одного элемента массива показан ниже.

```json
{"hit": "R1", "fragment": 5, "quote": "дословная выдержка из найденного текста"}
```

`history/RUN.search.json` хранит выдачу поиска. После сохранения ответа `history/RUN.json` содержит ту же выдачу, решение, ответ и цитаты с исходными указателями. Для перевода цитата также содержит текст исходного фрагмента. Для повторного обращения запустите новый поиск.

Для воспроизведения контрольных поисков вызовите `python rag.py batch-search checks/questions.json`. Команда выполняет отдельный поиск и сохраняет отдельную историю для каждого вопроса. Передача ответов чата на сохранение описана выше. [Ожидания до прогона](checks/expectations.md) предназначены для последующей оценки.

## Подготовка базы и обновления

- `extract.py` извлекает тексты в `prepared/original/`. Строки CSV читает стандартный модуль Python. `openpyxl` извлекает адреса ячеек и кэшированные значения Excel, `pypdf` сохраняет страницы, `python-docx` следует порядку абзацев и таблиц. SHA-256 связывает копию с точной версией оригинала.
- `prepared/ru/` содержит полные русскоязычные копии английских и французских документов с теми же номерами фрагментов. Готовые копии входят в проект. Перевод во время поиска не выполняется. [Отчёт подготовки](preparation.md) описывает сверку.
- [Реестр](registry.md) фиксирует допуск, версии и повторы на основании текста документов. Поиск учитывает действующие фрагменты, допущенные для запрошенной роли. Для перевода требуется запись смысловой сверки с SHA-256 точного текста фрагмента. Проверка распространяется на подписи и заголовки Excel, участвующие в поиске. Роль является локальным входным параметром без проверки личности.
- Поиск использует [BAAI BGE-M3](https://huggingface.co/BAAI/bge-m3) через Sentence Transformers. Модель поддерживает русский язык. Для документов и вопросов используется один снимок весов, пустой префикс и L2-нормализация. Сходство считается скалярным произведением, эквивалентным косинусному сходству нормированных векторов. NumPy хранит небольшой индекс локально и даёт возможность исчерпывающе оценить разрешённые фрагменты без отдельного сервера. Смежные правила CSV и абзацы Word группируются с сохранением исходных указателей.

Обновив источник, повторите `extract.py`, проверьте запись реестра и, если менялся английский или французский оригинал, обновите соответствующие переводы. Затем постройте индекс снова. Веса, рабочее окружение и индекс игнорируются Git.

Если нужен новый машинный черновик, скачайте конфигурацию, словарь и веса соответствующей OPUS-MT в `models/` и выполните `python translate.py --language en` или `python translate.py --language fr`. Команда пропускает неизменившиеся документы. Сверьте с оригиналом числа, условия, исключения, действия и получателей эскалации. Исправьте перевод и добавьте номер фрагмента в `reviewed_fragments`, а SHA-256 его текста в UTF-8 — в `reviewed_sha256` под тем же номером. При изменении текста отметка перестаёт действовать до следующей сверки. Для воспроизведения моделей загрузите указанные снимки.

Проверку допуска переводов можно повторить с помощью `python -m unittest checks.test_translation_review`. Она проверяет исключение изменённого текста и непроверенных заголовков при сборке поискового корпуса без скачивания весов.

```sh
hf download --local-dir models/en-ru --revision bb09c99d180016eac6819df3dae68edb1690fdee Helsinki-NLP/opus-mt-en-ru config.json generation_config.json tokenizer_config.json vocab.json source.spm target.spm pytorch_model.bin
hf download --local-dir models/fr-ru --revision 9e4e5772eccfebe66a3fde8a2d45427064cf6dc9 Helsinki-NLP/opus-mt-fr-ru config.json generation_config.json tokenizer_config.json vocab.json source.spm target.spm pytorch_model.bin
```
